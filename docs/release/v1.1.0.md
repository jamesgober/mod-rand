# mod-rand v1.1.0

Fixes from an independent review. Upgrade recommended for anyone who
used `tier2` string functions for tokens, or runs on Linux inside a
sandbox.

## What changed

- **Deprecated tier 2 string functions.** `tier2::random_string`,
  `random_alphanumeric`, `random_alpha`, `random_numeric` and
  `random_hex_string` share their names with the tier 3 functions, but
  their output is predictable. They still work through `1.x`; the
  deprecation note names the tier 3 function to use instead.
- **Plain-named modules.** `mod_rand::secure` (tier 3),
  `mod_rand::unique` (tier 2, without the deprecated string functions)
  and `mod_rand::seeded` (tier 1). They re-export the tier modules.
- **Linux `ENOSYS`.** On a kernel that has `getrandom` (3.17 or newer),
  an `ENOSYS` means a sandbox blocked the call. Tier 3 now returns that
  error instead of switching to `/dev/urandom`. Kernels older than 3.17
  still use `/dev/urandom`. If your sandbox profile reports `ENOSYS`
  for `getrandom`, allow the call.
- **Fewer system calls.** Tier 3 strings and `shuffle` read random
  words up to 256 bytes per call, so a 32-character token costs one
  system call. Nothing is buffered between calls.
- **Docs.** Tier 1 and tier 2 are never suggested for tokens, passwords
  or temp names in shared directories. The tier 2 uniqueness claim is
  corrected: values from different clock ticks are distinct with high
  probability, not always.

## Compatibility

- Additive only; deprecated items keep working. MSRV stays at Rust
  1.75.

## Upgrade

```toml
[dependencies]
mod-rand = "1.1"
```
